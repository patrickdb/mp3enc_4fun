# mp3enc

A lean MP3 encoder for the command line, written from scratch in TypeScript. It turns 16-bit PCM WAV files into
MPEG-1 Layer III files at constant bitrates (128, 160, 192, 256 kbps and every other standard one) or VBR.

No audio or codec libraries are used. The encoder only relies on Node's built-in `node:fs`. Everything else
(filterbank, MDCT, psychoacoustics, quantisation, Huffman coding, bit reservoir, bitstream) is implemented here
from the public ISO/IEC 11172-3 description of the format.

## Usage

```bash
npm install
npm run build
node dist/cli.js song.wav                       # 128 kbps CBR  -> song.mp3
node dist/cli.js song.wav -b 192 -o out.mp3     # 192 kbps CBR
node dist/cli.js song.wav -b vbr -q 2           # VBR, quality 0 (best) .. 9 (smallest), default 4
npm run mp3enc -- song.wav -b 256               # run from source without building
```

| Option | Meaning |
|--------|---------|
| `-b, --bitrate <kbps\|vbr>` | `32 40 48 56 64 80 96 112 128 160 192 224 256 320`, or `vbr` (default 128) |
| `-q, --vbr-quality <0-9>` | VBR quality (default 4) |
| `-o, --output <file>` | output file (default: input name with `.mp3`) |

Input: 16-bit PCM WAV, mono or stereo, 32 / 44.1 / 48 kHz. Bitrates that MP3 does not define (e.g. 169 or 296)
are refused with the list of valid ones.

After encoding, the tool reports the performance, for example
`Audio 30.00 s, encoded in 5.74 s: 0.19x real time`, and warns if encoding took more than half of the audio's
duration.

## How it works

```
WAV -> 32-band polyphase filterbank -> 18-point MDCT per band + alias reduction   (576 lines / granule)
    -> psychoacoustic model (ATH + spread masking, tonality)  -> allowed noise per scale-factor band
    -> two nested loops: inner = global gain meets the bit budget, outer = scale factors shape the noise
    -> Huffman coding (big values, count1, 32 tables, region split) -> bit reservoir -> frames
```

| File | Role |
|------|------|
| `src/wav.ts` | WAV parsing and validation |
| `src/polyphase.ts`, `src/hybrid.ts` | analysis filterbank, MDCT, alias reduction |
| `src/psycho.ts` | masking thresholds and perceptual entropy |
| `src/quantize.ts`, `src/scalefactors.ts` | power-law quantiser, scale-factor coding |
| `src/granule-encoder.ts` | the rate / distortion loops for one granule |
| `src/huffman.ts` | table and region selection, bit-exact Huffman writer |
| `src/frame-format.ts`, `src/frame-assembler.ts` | headers, side info, bit reservoir (`main_data_begin`) |
| `src/xing.ts` | VBR header frame (frame count, size, seek table) |
| `src/encoder.ts` | ties it together; CBR budgeting and VBR bitrate choice |
| `src/args.ts`, `src/cli-runner.ts`, `src/cli.ts` | command line |
| `src/tables/*-data.ts` | constants from the standard (generated, see below) |

Sources used for the research: ISO/IEC 11172-3 (Annexes B, C, D), Raissi, *The Theory Behind MP3*, Brandenburg,
*MP3 and AAC Explained*, and the *MPEG Layer3 Bitstream Syntax and Decoding* reference.

**Standard tables.** The Huffman code tables, scale-factor band boundaries and the 512-entry analysis window are
data defined by the standard. They are generated by `tools/generate-tables.mjs` from text extracted from public copies
of the standard, and validated while generating (every Huffman table is prefix-free with Kraft sum exactly 1).

### Deliberate simplifications ("lean and mean")

- Long blocks only (no block switching). Sharp transients can show some pre-echo.
- Plain left/right stereo (no mid/side or intensity stereo).
- No low-pass filter, scale-factor reuse (`scfsi`), pre-emphasis or ID3/LAME gapless tags. Players will hear
  about 25 ms of lead-in silence (the codec delay).
- The psychoacoustic model is a compact one working on the MDCT spectrum, not the full FFT based model of Annex D.

## Quality gates

```bash
npm run typecheck          # tsc --noEmit, strict + noUncheckedIndexedAccess
npm run lint               # ESLint + typescript-eslint strictTypeChecked + stylisticTypeChecked
npm test                   # unit tests (Vitest)
npm run test:acceptance    # builds, then runs the black-box acceptance tests against dist/cli.js
npm run check              # everything above
npm run coverage           # unit-test coverage
```

Development was test-driven: every module has unit tests that were written, seen to fail, and then made to pass.
`docs/acceptance-criteria.md` lists the acceptance criteria (AC-1 … AC-10). They run the real CLI and judge only its
output with checks that are independent of the encoder:

- the **mpg123** decoder (`mpg123-decoder`, WebAssembly) decodes every output without errors, with the right rate,
  channels and duration, and the audio matches the input (tone frequency/level, stereo separation, SNR);
- a **strict bitstream validator** (`tests/helpers/bitstream-validator.ts`, written from the ISO syntax) checks sync,
  headers, side info, reservoir pointers and that every granule's `part2_3_length` is consumed exactly;
- a **performance** criterion requires encoding to take less than half of the audio duration.

Measured on a 30 s stereo 44.1 kHz test song (`demo/`): 0.18-0.22x real time in every mode (worst case, full-scale
white noise, about 0.3x).
